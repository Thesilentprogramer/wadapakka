# Layer 2: real-time streaming + barge-in (deadline tonight 11:59 PM IST; aim to finish in ~3 hours)

The repo already has a working layer 1 (REST turn-taking WadaPakka reliability layer). Read README.md, docs/api_notes.md and the code first. Keep layer 1 working; add layer 2 as a new mode in the UI (toggle "Turn-based (L1)" / "Live streaming (L2)").

Goal: a full-duplex live call feel.
1. Backend WebSocket proxy (FastAPI): browser streams mic PCM (16 kHz mono 16-bit, via an AudioWorklet) to our backend; backend opens Prisma streaming `wss://api.vachana.ai/stt/v3/stream` with header X-API-Key-ID from GNANI_API_KEY (.env via python-dotenv; never print or log the key) plus the VAD headers per docs (e.g. x-min-silence-ms; check docs.gnani.ai for exact header names and message formats and record them in docs/api_notes.md). Forward `speech_start`, `processing`, and transcript events (`text`, `segment_id`, `utterance_id`, `latency`) to the browser.
2. Agent replies: on a final utterance, run the existing layer 1 logic (normalizer, verifier, state machine, idempotent ledger, handoff), then stream Timbre TTS back (prefer Timbre streaming over WebSocket `wss://api.vachana.ai/api/v1/tts` or SSE `/api/v1/tts/sse`; fall back to REST) and play chunks in the browser as they arrive.
3. Barge-in: when the caller starts speaking while the agent is talking (Prisma `speech_start`, plus a fast local energy-based VAD in the browser as a first trigger), immediately stop playback, cancel the in-flight TTS stream, and mark that agent turn "interrupted" in the timeline. If the interruption was mid read-back of a slot, the slot must NOT count as confirmed; re-ask after the caller finishes. Use echo cancellation (getUserMedia echoCancellation: true) so the agent's own voice doesn't trigger barge-in.
4. Handoff in streaming mode: if the caller says they want a human ("insaan se baat karni hai", "agent do", "manager"), stop talking instantly and show the one-line brief.
5. Metrics in the UI: per-turn latency (end of speech to first STT final, to first TTS audio byte), barge-in reaction time (speech_start to playback stopped), shown in the timeline and as a small stats bar. These are the demo's money shot.
6. Tests: unit-test the barge-in state logic (an interrupted read-back never confirms a slot; cancel is idempotent) with a fake event stream. Keep all existing tests passing.
7. Update README with a layer 2 section, the updated mermaid diagram, how to demo barge-in, and honest measured latency numbers from a real run (generate caller audio with Timbre and stream it through as a scripted test if you can't use a mic: write scripts/stream_smoke.py that streams a WAV file in real time to the backend and reports latencies).

Notes: don't use Inya/Agent Builder. Test on port 8001 (port 8000 is in use by the running layer 1 server). Don't try to git commit (.git is read-only in your sandbox). When done, print a short summary: what works, how to run, measured latencies, what's broken.
